KITES MATRIX KERNEL OPTIMIZATION REPORT
======================================

Measurement setup
-----------------
Simulator: five-stage RV5 pipeline with hazard detection and forwarding
Workload: 4x4 matrices of 64-bit integer elements
Counters: simulator instructions retired and simulated cycles
Correctness: all three matrix-kernel regression tests passed

Matrix multiplication results
-----------------------------
Both implementations multiply the same A and B matrices and produce the same
16-element output matrix.

Metric                         Scalar       Vector       Change
-----------------------------  -----------  -----------  --------------------
Instructions retired           1,060          269        791 fewer (74.62%)
Simulated cycles                1,317          334        983 fewer (74.64%)
Instructions/cycle               0.805         0.805      approximately equal
Cycle speedup                    --            --         3.94x

The speedup is simulated-cycle speedup for this 4x4 workload, not wall-clock
speedup. The cycle count includes the explicit NOP instructions in the vector
example that allow its scalar address dependencies to clear before vector
loads on the selected pipeline configuration.

How the vector instructions are used
------------------------------------
The vector implementation uses the existing KITES vector instruction subset:

1. vsetvli x0, t3, 24 configures a vector length of four lanes. Here t3 is 4,
   and vtype immediate 24 selects the implemented e64,m1 element format.
2. vle64.v loads four 64-bit matrix elements into a vector register. A row of A
   is loaded once and reused for all four output columns in that row. B is
   supplied in transposed row-major form so each column needed for a dot
   product is also available as one contiguous four-element vector load.
3. vdot.vv s3, v1, v2 is the custom KITES scalar-result dot-product instruction.
   It computes sum(v1[lane] * v2[lane]) for the active lanes and writes the
   reduction to scalar register s3. One such instruction replaces the scalar
   loop's four multiply-and-accumulate pairs for each output element.
4. sd stores the scalar dot-product result into the output matrix.

This workload produces 16 output elements. The vector version replaces the
per-element scalar reduction loop with one vdot.vv per output, amortizes each
A-row load across four outputs, and moves four operands per vector load. Address
calculation, loop control, vector loads, result stores, and explicit NOPs still
cost instructions and cycles; the reduction is not the entire program.

Cholesky results
----------------
Both implementations produce the expected lower factor for the same SPD
integer input.

Metric                         Scalar       Vector       Change
-----------------------------  -----------  -----------  --------------------
Instructions retired             422          362         60 fewer (14.22%)
Simulated cycles                  577          461        116 fewer (20.10%)
Cycle speedup                     --           --          1.25x

For each factor L[i][j], the vector kernel sets VL to j, loads the already
computed prefixes of rows i and j, and uses vdot.vv for their product sum.
Diagonal square roots remain scalar and are exact for the supported input
domain.

LU results
----------
Both implementations produce the expected unit-lower L and row-major U
factors for the same no-pivot input.

Metric                         Scalar       Vector       Change
-----------------------------  -----------  -----------  --------------------
Instructions retired             542          492         50 fewer (9.23%)
Simulated cycles                  707          607        100 fewer (14.14%)
Cycle speedup                     --           --          1.16x

The vector kernel sets VL to the current factorization row and uses vdot.vv
for the Doolittle product sums. A transposed copy of U is maintained as
scratch storage at 0x2500, making each U column contiguous for vector loads;
the externally visible U remains row-major. The kernel does not pivot, so
pivots must be nonzero and integer divisions exact.

The scalar baselines are preserved as examples/cholesky_scalar_4x4.s and
examples/lu_scalar_4x4.s. All percentages and speedups above are based on
simulator counters for these 4x4 test inputs, not wall-clock timings.

How to reproduce
----------------
From the repository root, build and run the focused regression tests:

    cmake --build --preset test-only
    ctest --preset test-only -R MatrixKernelsTest --output-on-failure

The tests compare outputs from scalar and vector kernels with expected results,
then assert that the vector versions retire fewer instructions and cycles. The
counts above were collected from the RV5 simulator's instructions_retired_ and
cycle_s_ counters during these tests.
